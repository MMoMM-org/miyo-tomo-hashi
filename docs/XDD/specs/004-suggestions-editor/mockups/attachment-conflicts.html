Attachments & conflict remedy

Each card gains an Attachments section built from suggestions[].attachments. An attachment whose destination is taken carries Tomo's attachment_conflicts entry inline, with its remedy and rename target. Try typing in the rename field: karte#1938.png, a:b.png , karte.png, or clear it.

Rules shown

  • Every card lists its attachments, worthy and suppressed alike, read-only. This is useful even with no conflict, because it shows what moves with the note.
  • A conflict is keyed by source. Every card that embeds the file shows the same conflict box, and an edit on one card updates all of them (scenario 3).
  • Remedy: rename (move under a new name), keep_in_inbox (leave the attachment in the inbox), ignore (no asset move; the embed resolves to the existing file). The default is whatever Tomo emitted.
  • The rename field sanitises visibly. The saved name is shown under the field and never changed silently. Removed: Tomo's 10 forbidden characters \ / : * ? " < > | + NUL, plus the link-breakers # ^ [ ], plus leading and trailing whitespace. A blank name is refused inline. A name that is also taken in the destination folder gets a warning but is not blocked, because Tomo's Pass 2 surfaces it independently.
  • The name field only shows when the remedy is Rename. Switching away keeps the typed name on the wire, so switching back restores it.
  • Open question: when no owning note is filed (all owners skipped or suppressed without Force Atomic), the remedy has no effect. The mockup still shows the box but marks it inert (scenario 2b). Alternatives: hide it, or disable the controls.
